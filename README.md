# Zycoo · 公司内部产品设计平台

本地 V1 垂直切片；需求依据见 docs/AI产品经理工作平台_设计大纲.md。客户与商机主数据属于既有销售平台，本平台仅接收匹配摘要。

## Docker Compose 启动（推荐）

当前目录已有 `.env`，直接运行：

```sh
docker compose up --build -d
```

访问 http://127.0.0.1:8000 ，账号与初始密码见 `.env`。也可使用兼容命令 `docker-compose up --build -d`。新机器先复制 `.env.example` 为 `.env` 并设置初始密码。前端和 Python 依赖在镜像中构建，无需宿主安装；已移除 CAD 引擎及其系统依赖和架构限制。

`./data` 持久挂载，复用本地已创建的演示项目；不要同时运行本地服务和容器服务。修改 `.env` 后运行 `docker compose up -d` 重建容器。若端口冲突，在 `.env` 设置 `PLATFORM_PORT=8001`。

```sh
docker compose logs -f platform
docker compose exec platform python -m pytest -q
docker compose exec platform python scripts/seed_demo.py
docker compose down
```

`down` 不删除宿主 `data`；备份时先停服务，再复制完整 `data` 目录（数据库及文件）。容器访问宿主模型服务时，MODEL_BASE_URL 使用 `http://host.docker.internal:端口/...`（Docker Desktop）。

## 本地 Python 启动（备选）

需要 Python 3.12、Node.js 20+。首次安装：

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cd frontend
npm ci
npm run build
cd ..
cp .env.example .env
```

当前机器已安装项目依赖，可直接运行 `./scripts/start.sh`。首次运行会生成随机初始密码并保存在权限为 600 的 `.env` 中，查看 BOOTSTRAP_USER / BOOTSTRAP_PASSWORD 登录。

如按上面的手动流程创建 `.env`，请修改初始账号密码；不要提交密钥。然后：

```sh
.venv/bin/python -m uvicorn backend.main:app --env-file .env --host 127.0.0.1 --port 8000
```

访问 http://127.0.0.1:8000 。接口说明 http://127.0.0.1:8000/docs 。开发前端运行 `cd frontend && npm run dev`，代理后端 8000。

## 产品主线与演示

公司知识接口/文件接入 → 结合竞品、客户反馈和销售市场输入 → 产品经理选定 premier 并确认产品基调 → AI 功能与软硬件拆解 → 产品经理确认最终方案 → PRD 和设计文件 → 评审反馈回到公司产品库。

1. 登录创建/选择项目，在“公司产品知识库”导入文本或文件；跨项目资料先搜索并引用。
2. 发布画像、研究竞品、录入客户/销售/市场反馈。在竞品研究卡片中直接点击“标记为 Premier 并分析产品页”：平台读取官网正文、生成有原文引句的产品分析和基调草稿，产品经理在“Premier 与产品基调”核对并确认。真实搜索只收录 Algo、Axis、Zenitel、TOA 等厂商的具体音频产品页；旧版普通网页结果从候选卡片隐藏，历史记录仍保留。
3. 产品经理确认基调后，平台立即依据 Premier、基调和授权公司资料自动生成待确认需求及软件、硬件、接口、验收拆解；尚无客户反馈的需求标记为待客户验证。需求默认折叠显示标题，可展开审核；产品经理可新增或移除需求。新增反馈会再生成相应需求。产品经理确认需求后自动生成候选功能方案，评审通过后确认最终方案。
4. 最终方案确认且有客户画像时自动生成 PRD 候选，项目页面自动载入；产品经理对比、编辑并保存。DOCX 下载和上传仍可用。
5. “设计文件与评审”上传专业工具完成的 CAD/STEP/结构图，关联需求、硬件功能和 PRD；修改后选上一版本上传，旧文件和逐版评审保留。
6. 前端顶部可切换中文或 English，选择保存在浏览器本地；界面文案即时切换，项目可见的业务文本在 English 模式下按权限调用已授权模型翻译，并在本地按项目缓存。翻译仅改变页面显示，编辑框、数据库记录和证据原文不改写；切回中文可看原文。AI 能力嵌入项目流程并按当前项目权限读取资料；无需单独创建智能体或训练新模型，不生成或对话修改 CAD。

模型或搜索未配置时可明确选择“显式演示 / 模板”。运行 `python scripts/seed_demo.py` 可创建标有“演示 2.3”的项目；工程附件只是说明文本，不是实际 CAD。旧演示项目保留，但需补确认产品基调才能继续生成。

## 验证与边界

```sh
.venv/bin/python -m pytest -q
cd frontend && npm run build
```

- 公司知识当前按授权项目聚合；接口使用登录会话和项目角色，未实现独立组织级权限、语义向量索引或外部业务库自动同步。
- 知识接口按来源系统、外部对象 ID、源版本幂等。同一对象上下文取最新接收版；显式跨项目引用固定到指定版本，每次读取重新检查权限。
- 模型上下文最多 40 条、约 10 万字符。TXT/Markdown/JSON（UTF-8）和 DOCX 可抽取文字，最多 6 万字符；PDF、图片、CAD 不解析内容，不声称已经理解。
- PDF、PNG/JPEG、SVG 和文本可预览；STEP、DWG 等专业格式仅归档下载，可另上传关联原件版本的预览附件。旧 CAD 文件仍可下载，生成及修改接口已移除。
- 基调变更后，需求拆解和方案须重新确认；历史 PRD、文件、评审保持原引用。工程方案是否可生产由专业人员判断。
- Tavily 音频检索已用公开关键词实际返回 Algo、Axis、Zenitel、TOA 的官方产品页；产品型号、规格与适配性仍须阅读原文核实。真实模型已用独立合成项目验证自动拆解、方案和 PRD；销售接口仍待联调。测试的演示内容不是实际客户/竞品事实。模型数据授权仍为服务器级开关。
- 官网正文使用 Tavily Extract 获取，解决本地代理 DNS 下直接读取官网失败的问题；仅自动分析可识别的厂商具体产品页。模型引句须逐字出现在已保存的网页正文中，分析草稿由产品经理确认。
- 业务页面以字段表单和可阅读的记录摘要展示项目数据；新生成的 PRD 正文不直接粘贴对象 JSON 或内部 ID，旧版 PRD 在页面预览时转换可识别的历史 JSON 区块。API 仍以结构化 JSON 交换数据。
- 基调确认后自动进入“需求与拆解”并显示任务状态；旧项目若当前基调尚无需求，进入该页会补排一次生成任务。设计文件关联在界面中显示名称和版本，内部 ID 继续留在数据库中用于追溯。
- 重复提交完全相同的 Premier 基准或产品基调不再新建版本。产品经理可在项目页面移除重复的基准、基调或需求；移除后的记录不再参与当前流程，历史引用和审计仍可追溯。删除最后一条需求不会自动重新生成，需主动点击“重新提取”。
- 单实例 SQLite、本地文件与进程任务池；PRD 导入保存文本和表格，不保证 Word 复杂排版；低保真原型仍采用可编辑模板。

## admin 账户配置

admin 登录后进入左侧“账户配置”，填写登录名、初始密码（至少 8 位）、销售/市场角色并勾选可访问项目，即可创建账户。已有销售/市场账户可修改角色、项目授权、启用状态或重置密码；保存配置会撤销该账户旧会话，需重新登录。未分配项目的账户不能读取任何项目，销售/市场不能自行创建项目或访问管理员接口。已有管理员凭据及项目数据保留。


`.env` 中的 BOOTSTRAP_PASSWORD 只用于首次创建管理员，不会在重启时覆盖已保存密码。若忘记原密码，可在项目目录执行以下命令，按提示输入并确认新的至少 8 位密码（不会回显）：

```sh
docker compose exec platform python scripts/reset_admin_password.py
```

此工具只有实际执行并输入新密码才会修改管理员密码，并撤销旧会话。账户配置页面仅管理销售/市场账户。
