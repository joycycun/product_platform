# V1 实施与接口契约

## 页面与操作

公司设计库跨项目权限检索与引用。项目流程为概览（新建、任务）→画像（发布版本）→竞品（真实搜索、读取、人工资料）→基准（证据核实、冻结快照）→匹配客户（模拟或正式上游摘要、反馈）→需求与实现拆解→候选方案与评审→PRD 候选/编辑/版本→设计文件上传/版本/评审→反馈入库。

## 数据模型

Project 1:N Membership；项目 1:N 不可变 Record。Record.kind 覆盖 profile、competitor、source、facts、baseline、feedback、need、proposal、review、selection、prd_candidate、prd、product_tone、knowledge、upload、reference、audit。需求引用反馈和基准，方案引用需求与基准；PRD/设计文件固定引用基准与产品基调、画像、方案和需求 ID。修改追加版本，不重写旧记录。

Match 唯一键为 project_id + source_system + external_customer_id，event_id 幂等；客户主数据保留在销售平台。File 绑定项目/对象并逐请求鉴权。Job 保存输入、状态、失败原因与结果。SQLite migrations 记录 schema 版本，数据目录默认 data/。

技术栈：React/TypeScript/Vite，FastAPI/Pydantic，SQLite WAL，本地受控文件存储，ThreadPoolExecutor。单项目当前主线，后续扩展分支与产品线。

## 销售正式接口 v1

鉴权：HTTPS（正式部署）+ Authorization: Bearer <SALES_TOKEN>。source_system 必须与 SALES_SOURCE_SYSTEM 一致。令牌仅服务器配置，不进入浏览器。待双方确认正式令牌分发/轮换、地址与网络白名单。

GET /api/integrations/sales/profiles 返回所有已发布项目的最新画像及不可变记录 ID。上游可轮询；画像事件通知尚未实施。画像字段 industry、scenario、region、scale、buyer、needs、budget、exclusions，未知为空。

POST /api/integrations/sales/matches 请求：

```json
{
  "event_id": "sales-event-0001",
  "project_id": "本平台项目ID",
  "profile_version": "本平台画像记录ID",
  "source_system": "company-sales",
  "external_customer_id": "上游唯一客户ID",
  "customer_name": "授权展示摘要",
  "industry": "教育",
  "region": "华东",
  "owner": "负责销售",
  "reasons": ["命中学校走廊使用场景"],
  "hard_conditions": ["教育行业"],
  "preferences": ["远距离可见性"],
  "crm_url": "https://sales.company.example/customers/ID",
  "updated_at": "2026-11-09T12:00:00+00:00",
  "action": "upsert"
}
```

成功 accepted；同事件 duplicate；401 身份失败，403 来源系统不匹配，409 画像过期/时间倒退/事件冲突，422 字段错误，503 未配置。withdraw 表示撤回，保留审计与摘要状态。网络/5xx 使用相同 event_id 指数退避重试；409 需重新读取画像或核对版本。客户更新时间必须有时区。匹配不等于访谈需求。

POST /api/projects/{id}/mock-sales 仅项目可写成员调用，source_system=mock-sales、provenance=mock_upstream；不冒充正式接口联调。

待上游确认：字段字典、客户撤回隐私保留期限、画像轮询频率、销售原平台 URL 权限、更新顺序与时钟精度；本平台不需要合同/回款/商机阶段接口。

## 新主线与接口

- `POST /api/projects/{pid}/knowledge`：title、content、source_system、external_id、source_version、locator；同源同版本同内容返回原记录，不同内容返回 409。
- `POST .../competitors/{rid}/premier`：产品经理在竞品卡片中标记 Premier。真实模式通过 Tavily Extract 读取已识别厂商的具体产品页，生成带原文引句的基准事实与待确认产品基调草稿；演示模式明确标注未读取官网。返回任务 ID，完成后结果含 baseline、candidate 和 source。
- `POST .../product-tones`：baseline_id、target_users、core_value、positioning、design_principles、differentiation、constraints、out_of_scope、rationale、confirmed=true、generation_mode；仅 owner/product 确认，变更保留历史与影响记录。相同内容重复提交返回已有版本。确认后无论有无客户反馈都自动排入需求拆解任务；无反馈需求的 `feedback_ids=[]`，正文标记待客户验证。
- `POST .../baselines` 对当前完全相同的基准幂等；`DELETE .../baselines/{rid}`、`DELETE .../product-tones/{rid}` 仅 owner/product 可执行，将记录归档并从当前列表移除，历史对象仍可按 ID 追溯。
- `POST .../feedback`：已有当前基调时只针对新反馈自动排入需求拆解；`POST .../needs/{rid}` 在产品经理确认需求后自动排入候选方案生成；`POST .../proposals/{rid}/select` 在评审通过且有画像后自动排入 PRD 候选生成。返回的 `next_job` 可查询任务状态，前端在项目内轮询并载入候选。
- `POST .../needs`：产品经理手工新增当前基调下的待确认需求。`DELETE .../needs/{rid}`：归档当前需求及其版本链；历史引用仍可读取。
- `POST .../needs/ensure`：进入需求页时检查当前基调是否已有需求或正在运行的任务。若旧项目尚未生成需求，幂等补排任务；人工移除最后一条需求后返回 `empty`，不会自动重新生成，需主动使用 `POST .../needs/generate`。基调确认后页面自动转到需求页并显示生成进度。
- `POST .../files`：multipart 的 file 与 metadata JSON。metadata 含 purpose、previous_id、note、need_ids、proposal_id、hardware_feature_indexes、prd_id、preview_of_id。索引与不可变方案 ID 共同定位硬件功能；全部关联须属同项目并相互一致。
- `GET .../files/{rid}/versions`：返回同一文件的版本、下载地址和逐版评审。rid/previous_id 为 upload 记录 ID，下载 URL 中为 file ID；两者不同。并发上传旧父版返回 409。新版本应提交完整关联字段，前端默认带入所选上一版本的关联。
- `POST .../reviews`：target_id 指具体文件或方案版本。评审与客户反馈直接进入权限内公司资产搜索，不改变旧文件。
- `GET .../agent-context`：当前项目、基准、基调和授权资料。旧版 `POST .../assistant` 暂保留接口兼容，前端不再提供单独的项目智能体入口；研究、需求、方案和 PRD 能力嵌入项目主线。
- `POST .../translate`：仅登录且拥有项目访问权的用户可提交 English 模式下可见的项目业务文本；需已配置模型及 `ALLOW_MODEL_PROJECT_DATA=true`。按项目和源文本哈希缓存英文译文，只返回显示译文，不修改原始记录或输入内容。单次最多 12 段、总计 1.2 万字符。
- 搜索、模型凭据仅服务端使用；未配置真实模式返回错误，不静默回退演示。

文件最大 20 MB。支持上传 STEP/STP、IGES/IGS、STL、DWG/DXF、SLDPRT/SLDASM、FCSTD、3DM、IPT/IAM、PRT/ASM、PDF、PNG/JPEG、SVG、TXT、Markdown、JSON、DOCX。可在线预览 PDF、PNG/JPEG、SVG、TXT/Markdown/JSON；其余显示明确提示并提供下载。工程文件不执行、不编辑，预览隔离脚本。

新增记录沿用不可变 records 存储，不删除已有数据。旧文件相对路径和宿主绝对路径兼容下载，旧 CAD 归档仍可读取。账户配置角色和禁用状态继续生效。
